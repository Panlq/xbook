哈希表的实现都有一个索引计算方式，一般是取模运算，能避免结果溢出 out of range

## 1. 传统取模运算的问题

传统的取模运算（%）在计算机中执行效率较低，因为它需要进行除法运算，而除法运算在 CPU 中是一个相对耗时的操作。

## 2. 位与运算优化的原理

m 是桶的容量

> capMask = m - 1
>
> x = hash & capMask

使用位与运算（&）来替代取模运算（%）的原理是：

1. 前提条件

   - 缓冲区大小必须是 2 的幂（如：2, 4, 8, 16, 32...）
   - capMask = 容量 - 1

2. 二进制特性

   - 当容量是 2 的幂时，capMask 的二进制表示全为 1
   - 例如：
     - 容量为 8：
       - 8 的二进制：1000
       - capMask (7) 的二进制：0111
     - 容量为 16：
       - 16 的二进制：10000
       - capMask (15) 的二进制：01111

3. 计算过程示例 假设容量为 8，计算索引 11 的实际位置：

```plaintext
11 的二进制：    1011
capMask (7)：    0111
11 & 7 =         0011 (十进制 3)
```

## 3. 性能优势

1. CPU 指令效率

   - 位与运算（&）通常只需要一个 CPU 周期
   - 取模运算（%）需要多个 CPU 周期，包含除法运算

2. 延迟对比

   - 位与运算：O(1) 固定时间
   - 取模运算：相对更慢，尤其是对于大数

## 4. 使用限制

这种优化方式有一些限制：

1. 容量必须是 2 的幂
2. 需要预先计算 capMask
3. 不适用于需要任意容量的场景

## 5. 如果快速计算任意数字最近的 2 次幂

```go
func nextPowerOfTwo(n uint64) uint64 {
    n--
    n |= n >> 1
    n |= n >> 2
    n |= n >> 4
    n |= n >> 8
    n |= n >> 16
    n |= n >> 32
    n++
    return n
}
```

### 1. 算法原理解析

以计算 11 的下一个 2 的幂（16）为例：

1. 初始值 : n = 11

```
二进制：00000000 00001011
```

2. 第一步 : n--

```
n = 10
二进制：00000000 00001010
```

3. 位操作

```
原始值：    00000000 00001010
右移1位：   00000000 00000101
或运算后：  00000000 00001111

右移2位：   00000000 00000011
或运算后：  00000000 00001111

右移4位：   00000000 00000000
或运算后：  00000000 00001111

(后续移位因为都是0，结果不变)
```

4. 最后 n++

```
结果：00000000 00010000 (16)
```

### 2. 为什么这样做有效？

1. **初始递减**
   - n-- 的目的是处理本身就是 2 的幂的情况
   - 如果不减 1，当输入是 8 时会得到 16
2. **连续右移或运算**
   - 通过不同位数的右移，将最高位 1 右边的所有位都填充为 1
   - 每次移位都覆盖更多的位，确保不遗漏
3. **最终递增**
   - n++ 将所有连续的 1 进位，得到下一个 2 的幂
